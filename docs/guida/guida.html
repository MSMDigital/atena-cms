01 — Prima di iniziare

Tre cose accese. Poi si parte.

Il CMS è il motore: admin, database, login, immagini, moduli, pubblicazione. Il sito è un template che si installa a parte. Un'installazione, un sito, un database.

CosaPerché
Node.js 22.12+Il Mac usa di default una versione più vecchia. In ogni terminale nuovo: . ~/.nvm/nvm.sh && nvm use 22
Docker DesktopAcceso. Ospita MySQL, sulla porta 3307.
Cartella del progettoatena-cms. Ogni comando di questa guida parte da lì.

Il database

npm run db:up      # avvia MySQL e aspetta che sia pronto
npm run db:down    # lo spegne, i dati restano nel volume

Due modi per provare

Modo A

Istanza di sviluppo

Quella già installata. Il modo più rapido per toccare admin, stile, immagini, moduli e template.

Modo B

Installazione da zero

Una copia separata, con il suo database. Serve a vedere la procedura guidata. Non tocca la A.

Regola

Le credenziali non si scrivono mai nei comandi né nei file del progetto. Stanno nel .env (ignorato da git) o nelle variabili d'ambiente.

02 — Modo A · Istanza di sviluppo

Avvia. Accedi. Tocca tutto.

  1. Avvia l'app. L'admin si apre su http://localhost:3000/admin.

    npm run dev

  2. Accedi con webdeveloper@msmdigital.it e la password che hai scelto. Se non la ricordi, se ne genera una nuova. Compare una sola volta, alla riga «Password (mostrata una sola volta…)».

    node scripts/create-user.mjs --email webdeveloper@msmdigital.it \
  --name Atena --role admin --reset

  3. Vedi il sito pubblico, in un secondo terminale. I moduli arrivano all'app sulla porta 3000, quindi l'invio funziona. Dopo ogni modifica ai contenuti usa Pubblica nell'admin: rigenera il sito.

    npm run build     # genera il sito statico in dist/
npm run serve     # lo serve su http://localhost:4173

Cosa provare

DoveCosa
PagineModifica testi e blocchi: l'anteprima cambia subito. Riordina, duplica, nascondi, aggiungi.
StileColori, dimensioni dei titoli, effetto dei pulsanti, con anteprima dal vivo.
ImmaginiCarica (vengono ricodificate in WebP) e scegli il punto focale.
Dati del sitoContatti, menu, consenso alla mappa (integrato o iubenda).
EmailServer SMTP ed email di prova. Senza SMTP le richieste si salvano lo stesso.
RichiesteCompila un modulo dal sito pubblico e ritrovalo nell'elenco.
TemplateAttiva Starter, con blocchi propri. I contenuti si sostituiscono con quelli di esempio, con copia di sicurezza in data/backups/.
UtentiNessuna pagina di gestione: si creano da riga di comando, ruolo editor o admin. L'editor vede solo pagine e blocchi condivisi.
Attenzione a .next

npm run dev e npm start usano la stessa cartella .next. Se passi dall'uno all'altro l'admin si rompe: fermalo e rifai npm run build:admin.

03 — Modo B · Installazione da zero

Una copia pulita. Zero rischi per la A.

Il modo automatico

Database e cartelle temporanei. Percorre tutti i passi: chiave, requisiti, database, primo admin, zip del template, template dall'admin, cambio di template, rimozione. Alla fine pulisce. Serve l'admin già compilato (npm run build:admin) e Docker acceso.

node scripts/e2e-install.mjs

A mano, per vedere il wizard

  1. Ferma la A con Ctrl+C. Due copie in sviluppo nella stessa cartella non convivono.

  2. Crea un database vuoto. La password di root la legge il container: non va scritta.

    docker exec atena-cms-db sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" \
  -e "CREATE DATABASE atena_cms_prova \
      CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci; \
      GRANT ALL ON atena_cms_prova.* TO \"cms\"@\"%\";"'

  3. Prepara lo zip del template. Finisce nella cartella del progetto, per esempio starter-1.2.0.zip.

    npm run template:pack -- templates/starter

  4. Avvia una copia isolata. Cartelle a parte e variabili del .env di sviluppo svuotate: altrimenti la procedura vede il database già installato e si crede installata.

    P=/tmp/cms-prova
env DB_HOST= DB_PORT= DB_NAME= DB_USER= DB_PASSWORD= DB_ROOT_PASSWORD= \
    SETTINGS_SECRET= IP_HASH_SECRET= APP_ORIGIN= TRUST_PROXY= INSTALL_TOKEN= \
    CMS_TEMPLATE= CMS_TEMPLATE_DIR= SMTP_HOST= MAIL_FROM= \
    DATA_DIR=$P/data TEMPLATES_DIR=$P/templates ENV_FILE=$P/.env \
    SITE_OUT_DIR=$P/dist MEDIA_DIR=$P/media \
    npx next dev -p 3100

03 — Modo B · Il wizard

Apri /install e segui i passi.

Vai su http://localhost:3100/install. Cinque passi e il sito è pubblicato.

PassoCosa fai
ChiaveLa trovi nel terminale, alla riga «Chiave di installazione…», e in /tmp/cms-prova/data/install-token.
RequisitiDevono essere tutti a posto: Node, immagini, permessi, cartelle scrivibili.
DatabaseHost 127.0.0.1, porta 3307, nome atena_cms_prova, utente cms e la DB_PASSWORD del tuo .env.
Primo adminNome, email, password di almeno 12 caratteri.
TemplateCarica lo zip del passo 3 e indica l'indirizzo pubblico del sito. Si installano i contenuti di esempio e il sito viene pubblicato subito.

Finito, /install si chiude per sempre e la chiave non serve più. Accedi da http://localhost:3100/admin.

Password del database

Non può contenere $ ' " \ ` #: il file .env non li conserva in modo affidabile.

Pulizia

docker exec atena-cms-db sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" \
  -e "DROP DATABASE atena_cms_prova"'
rm -rf /tmp/cms-prova starter-1.2.0.zip
npm run build:admin   # la copia in sviluppo ha sovrascritto .next

05 — Se qualcosa non va

Errori noti. Con la causa.

Messaggio in consoleCosa significa
«unsafe-eval» in sviluppoRisolto. Con npm run dev la politica di sicurezza ammette eval solo in quella modalità: serve al refresh automatico di React. In produzione no.
«…from origin 'null' … _devMiddlewareManifest.json»Una pagina dell'admin era finita dentro l'iframe dell'anteprima, che ha origine null perché isolato. Ora l'anteprima riceve HTML dall'editor e, senza sessione, /admin/preview risponde 401. Se lo rivedi: ricarica (la sessione può essere scaduta) e segnala pagina e browser.
«Failed to load resource» per favicon.icoInnocuo. L'admin non ha un'icona del sito.
L'admin si rompe passando da dev a startStessa cartella .next. Rifai npm run build:admin.

Cosa NON è stato provato

Coerente con come lavoriamo: meglio dirlo prima che scoprirlo dopo.

  • L'installazione su un server vero (Infomaniak).
  • L'invio email con un SMTP reale.
  • iubenda con un account vero: finora solo uno script finto.
Sicurezza dei template

Un template è codice. Il suo isolamento ha limiti dichiarati (rete e segnali non sono limitati da Node; il JavaScript del template gira nel sito pubblico). Prima di installare template di terzi leggi «Template e sicurezza» in docs/architettura.md.
